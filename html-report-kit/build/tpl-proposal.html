01 / 结论

一页纸：做什么，不做什么，要你定什么

做
把评审材料从「长文档」换成「可批注的图页」：编排图、排期、架构、风险一次给全，评审会只看差异点。
不做
不做实时拖拽编辑器。这一版只做「静态图 + 批注回写」，把实时留给第二轮验证后再定。

02 / 编排

七个节点，两处并行，两道门禁

悬停任一节点，其余会自动淡出——这是纯 CSS 的 :has()，没有 JS。

为什么「图显前置」排在骨架之前
图没确认就写代码，返工成本是图阶段改动的 5-10 倍。把错误提前到最便宜的时刻。
为什么「内容填充」能和「骨架」并行
因为两者共用 data-block 契约：骨架先占位，内容按块灌入，互不阻塞。

唯一「致命 × 高概率」的一项
AI 整篇重写覆盖人工修改。这不是小概率事故，是默认行为。对策见架构层：真相必须在 data-block 契约上，且宿主侧做丢块自检。
被低估的一项
决策堆积。每张决策卡都很轻，但没人拍板时它们会静默累积成"看起来都定了"的假象。所以卡片必须显示「不选则默认 X」。
06 / 验收

两道门禁，四种不过的处理

G1
图确认门（W2 末）

编排图、排期、架构三张图全部通过，才允许写第一行代码。

G2
可用性门（W5 末）

非作者本人能在不看说明的情况下完成一次完整评审操作。

不过的情形处理谁能决定记录在哪
图有争议回到 G1 重画，不进代码项目负责人决策卡 D-xxx
图过了但实现跑偏以图为准改实现，不改图执行方变更记录
图本身错了停下来改图，并记录为什么当初没看出来负责人 + 评审复盘条目
