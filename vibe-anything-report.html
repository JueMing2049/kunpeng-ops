结论一 · 「生产级」的真正判据是第二次能不能做出来
2024 年的 3D 生成是抽卡：一次一世界，好的一次截图发推，坏的重开。 2026 年的变化是可复现：单文件 HTML、逐帧函数、参数化 Schema、Git diff。 当一个 3D 场景能被 git log 追踪、被 JSON Schema 约束、被 CI 重新渲染， 它才从「作品」变成「产线」。这条界，比「画质好不好」重要得多。
结论二 · 七条产线不是七个赛道，是一条光谱上的七个采样点
左端是纯代码确定性（HTML PPT、动效视频），右端是生成模型随机性（白模重绘成片）。 中间的低精度游戏与双轨建模，是两种「用降低精度换取完成度」的策略。 选错位置，不是工具问题，是把自己的需求放到了错误的确定性档位上。
结论三 · 最大跃迁来自「工具调用」，不是「视觉理解」
BenchCAD 上，同一个模型带工具与不带工具能差出 40 个百分点（DeepSeek 41.2 → 81.6）。 这意味着 3D 能力的本质是「能写脚本、能跑起来、能看结果、能改」的闭环，而不是把三维形状「想」得更准。 这解释了为什么 Kimi 要强调「无需 MCP 也能直写 Blender/CAD 脚本」—— 脚本权限就是 3D 能力本身。
结论四 · 声音是唯一横跨光谱两端的一类
同一件「配一段音乐」，既能用几十行代码合成（Strudel / Tone.js：可逐帧复现、体积以 KB 计、能与画面事件绑定）， 也能交给生成模型（Suno / SFX v3：质感惊人、一次一版、不可复现）。 所以它是最好的试金石——工作流只会走右端，说明还没工程化；只会走左端，说明还没上审美。
结论五 · 决定账单的不是单价，是「平均几次成型」
同一个任务，V4.1 Flash 谷时单轮约 ¥0.05，Opus 5.5 约 ¥1.71，差 31.8 倍； 但把重抽次数从 1 次提到 10 次，任何模型都翻十倍。左端产线写完代码后本地重渲染不烧 token， 右端产线每次抽卡都要重付一遍——这才是「代码即产线」在经济上的真正含义。 详见 08 Token 成本参考；09 官方案例集 里两个独立实测账本， 都把长链路任务的实际均价落在 ≈¥0.05 / 百万 token——因为九成以上的 token 是缓存命中的重复上下文。
◈
一个必须说清的术语滑坡
「Vibe Anything」在传播中常被当成「什么都能生成」。更准确的读法是 「任何形态都能被表达为可执行代码，并被同一套工程流程收编」。 前者是营销，后者是这一年真正发生的事。
02 / 能力拐点

三个模型，一条被工具撬起来的曲线

2026 年 10 月是密集的一个月：17 日 DeepSeek V4.1-Flash-1017，24 日 Kimi K3.1 Pro， 中间夹着 Claude Opus 5.5 与 GPT-6 Astra 的持续发酵。三家都指向同一件事——从零构建完整项目。

BenchCAD 是什么 给模型多视图渲染图，要求它写出 CAD 代码重建 3D 模型，再用 Voxel IoU 打分。它测的不是「画得像」，是「结构对不对、代码跑不跑得通」。

注意这张图里最反直觉的一处：排序在带工具与不带工具之间会翻转。 不带工具时 Opus 领先 Kimi 不到 1 分（73.0 vs 72.8），Fable 却掉到 60.6、DeepSeek 只有 41.2。 也就是说，「谁更强」这个问题，离开权限设定就没有意义。 这对选型的直接含义是：先问你的工作流给不给模型跑代码的权限，再问哪个模型分高。

03 / 确定性光谱

七条产线，其实排在同一条轴上

04 / 七条产线

逐条拆：代表作、工具链、判据、坑

每条产线只回答四件事：谁做出来了、用什么做的、怎么判断合格、最容易死在哪。

4.1动效视频 / MG —— 增长最快、门槛最低

这是目前案例最密集的一类：Opus 5.5 的 1019 条案例中，「动效视频/动画/音乐」占 400 条， 是所有分类里最大的一块。技术栈极度收敛：Canvas / SVG / GSAP / GLSL / Three.js / Web Audio。

代表作
713 条 prompt / 418 个现场重制被收进 awesome-opus5-5-videos，并有 Skillry 做「原片 vs 重制」并排对照； mg-styles-15 用 15 句提示词长出 15 种动效风格，源码全开；video-shotcraft 把电影级产品片拆成 124 张镜头配方卡。
判据
一、节奏是否可数：把时间轴交给 frame 而不是 setTimeout； 二、是否单文件可交付：双击打开就能播； 三、是否可参数化：换文案、换配色不用重写。
坑
「录屏即视频」是当前最脆的一环
浏览器实时播放 → 屏幕录制，会掉帧、会受机器负载影响、无法批量。要走产线，必须换成 headless 逐帧渲染（Remotion / HyperFrames / MotionGit 的 renderFrame）。

4.23D Web 体验 —— 交互性最高的确定性产物

这一类的共同形态是「打开链接就能走进去」。它比视频多了一维：观众可以拒绝按你的路线看。 因此它天然要求程序化——不可能给每一个视角都手工摆一遍。

4.3动画 HTML PPT —— 确定性最高，被严重低估

这一类在社区案例里几乎没有独立分类（1019 条里最接近的只有 1—2 条），但工程化程度反而是最高的： 它是唯一一种产物本身可被纯文本 diff 的形态。

html-ppt-skill
36 套主题 / 15 套整稿 / 31 个单页版式 / 47 个动画（27 CSS + 20 Canvas FX），零构建，双击即开。
frontend-slides
19k+ star 的 Claude Code 技能，单文件内联、12 套极简主题，可直接从旧 PPTX 提取内容重排。
Bento
560KB 单文件 ≈ 完整 PPT + 编辑器；文档以 JSON block 存在 HTML 顶部，任何模型都能直接改；同 id 元素自动 morph。

Bento 的设计值得单独说一句：把文档数据以纯 JSON 放在文件顶部，等于给了所有模型一个稳定的写入接口 （window.bento.loadDoc）。这比「让模型重写整个 HTML」可靠一个数量级。 判据：① 断网可播 ② 键盘可导航 ③ 打印成 PDF 不走形 ④ 改一行 CSS 就能换整套气质。

4.43D 建模 —— 必须分成两轨看（下一节展开）

这是最多人混淆的一档。「AI 会 3D 建模」这句话里其实藏着两条完全不同的技术路线， 它们的成本结构、可编辑性、失败模式都不一样。详见 05 建模双轨。

4.5低精度游戏 —— 用「精度换完成度」的最优解

这是本年度性价比最高的一档：把美术精度压到极低，把玩法与系统完整度拉满。

体素 / Voxel
Blender 体素 JRPG 影像、NEO-KASHIMA 体素科幻小镇、乐高化的 KAFD 金融区（3149 个现成零件含楼梯）。 体素的妙处是：模型丑得合理，观众不会拿「真实感」要求你。
ASCII
Asciidia 让 LLM 实时「召唤」任意物件并推断其机制（龙能骑、工厂能产、火剑带火伤）； Astra 做出整座 ASCII 城市，行走时无限程序化重生成。 渲染不上场，逻辑就必须扛住全部重量。
像素 / 涂鸦
Circles of Ash 全部精灵与图块由 Python/Pillow 用代码画出来，而非调图像 API； 《绘卷奇谭》折纸风 Godot；HD-2D 麦田沙盒。 「用代码画画」是这一档的技术内核。

当渲染不是强项时，逻辑与行为必须承担全部重量。

— 关于 Asciidia 的一条评论，也适用于整个低精度赛道

为什么它是最优解：3D 建模的失败模式是「形不准」，而生图的失败模式是「不可交互」。 低精度同时绕开了两个：形不准可以被风格吸收，交互则完全由代码保证。 判据：能否在 10 秒内让玩家理解规则；是否有「再来一次」的动机（而非看完即走）。

05 / 建模双轨

纯代码建模 vs 脚本驱动 Blender

同样叫「AI 建模」，一条产出的是能被浏览器直接执行的几何，另一条产出的是能被专业管线接手的资产。 分不清这两轨，就会在错误的成本曲线上反复烧钱。

维度纯代码建模脚本驱动 Blender / CAD
代表做法Three.js 几何拼装、SDF 隐式体、GLSL 着色、Geometry Nodes 移植到 Web模型写 Python 直控 Blender；MCP 连运行中的 Blender；CadQuery / FreeCAD 出图
产出物单文件 HTML / 实时场景，双击即开GLB / FBX、渲染序列、DXF 图纸、4D 施工动画
形准能力弱—中（靠审美与规则弥补）强（借专业内核的布尔、倒角、UV、绑定）
可复现性极高：代码即几何，参数即变体高：脚本可重跑，但依赖 Blender 版本与插件
环境成本零：一个浏览器高：本地 Blender、Python 环境、显卡渲染
典型翻车「截图很好看，转起来就穿模」「脚本跑通了，但资产不可用（法线/UV/命名全乱）」
适合谁Web 交互、程序化世界、需要批量变体影视级镜头、产品级资产、需要进后续专业管线

5.1几个能说明差距的实测

  • 纯代码的天花板：天坛祈年殿 773 个部件纯代码搭建，还自行纠正了材质；游戏级章鱼、巨龙绑定则在 Blender 内完成建模到动画。
  • Blender 轨的效率：15 分钟完成风车建模 + 绑定 + 材质 + 动画；30 分钟把原画转成可用的 Blender 模型；39 分钟分析外骨骼弱点并重建完整模型。
  • 第三条路——AI 出模 + 脚本精修：Tripo H3 出网格与骨骼，模型负责贴图、辅助骨骼、权重与动画；单图箱庭房间 = Tripo × Opus × Blender。
  • 工程化的极限样本：新干线模型含 5112 个物体 / 430 个座椅；UE 赛博朋克城市 5 小时做出 5600 万面 Nanite + Lumen。

7.2三个时钟：卡点为什么总差几帧

这是本节最值钱的一段。所有「卡点不准」的抱怨，根子都不在模型，在三套时钟的最小公倍数不整。

7.3把音乐变成可查询的数据

既然拍点不落在格线上，就不能「边播边猜」，只能先把音频解析成事件表，再让画面按表调度。 这就是「音频工程化」的全部内容，也是代码侧该干的事。

L1
Bar 级 —— 场景切换

一小节一个场景。用于段落推进、地图切换、章节卡。

L2
Beat 级 —— 剪辑点

主拍切镜。这是「卡点」最常被指的那一层，也是最容易看出差 2ms 的一层。

L3
Sub-beat 级 —— 运动强调

把动作的加速、回弹、拖尾挂在细分拍上，画面会「有弹性」。

L4
Onset 级 —— 视觉瞬态

打击乐起音的毫秒级落点，驱动闪光、粒子迸发、镜头微震。

L5
Energy 级 —— 色彩与速度曲线

用整段的能量包络控制饱和度、运动速度、景深。这一层决定「像不像 MV」。

五级量化不是玄学，它是把波形压成一张可以 query(t) 的表。 一旦有了这张表，卡点就从「手感」变成了「查表」—— 而这正是 LLM 最擅长的事：写一个解析器，然后按表生成调度代码。 

// 思路示意：先解析，再调度，最后才渲染
const grid = analyze(audio);          // BPM / onset[] / section[] / energy[]
const events = grid.beats.map(b => ({
  frame: Math.round(b.time * fps),   // ← 关键：量化到帧网格
  kind: b.energy > .8 ? 'cut' : 'accent'
}));
renderFrame(frame, { events });       // 纯函数，可跳帧、可重跑

7.5判据与坑

四条验收线
① loop 是否无缝：把结尾接回开头听 10 次，有没有「咔」；
② 是否与事件绑定：同一个音效能不能在第 137 帧精确触发；
③ 授权是否覆盖商用：不是「能生成」，是「能卖」；
④ 时长是否够：SFX 单次硬上限 30 秒，超过就得靠 loop 拼。
四个真坑
① 开源权重 ≠ 无约束：MiniMax 要求界面署名，超 2000 万美元年收入需书面授权；
② 托管 ≠ 拥有：Suno 的输出留在平台工作区，付了订阅才被授予权利；
③ 计数不可靠：提示词写「敲四下」不保证四下；
④ 音频是挂钟：.motion 规范要求「时序不得依赖挂钟」，内嵌音视频必须单独适配、不得静默丢弃——这是确定性渲染与音频的天然冲突点。

音乐创作工具不一定要是复杂的图形界面。有时候，一个简洁的编辑器和一套精心设计的 API，就能释放巨大的创造力。

单轮成本 = miss/1e6 × P_miss + hit/1e6 × P_hit + out/1e6 × P_out

9.5三个把「愿望」变成「交付」的坑

① 输出上限给少了，交付物会断在半截
CSDN 第一次把 max_tokens 设为 16,000：14,262（89.1%）花在 reasoning，只剩 1,738 写代码， HTML 写到 4,771 字节被截断，finish_reason: length、页面全白。改到 48,000 后一次性跑通（21,333 tokens，思考占 71.9%）。 代码/Agent 任务建议 max_tokens ≥ 32,000，并按「代码量 × 7–10 倍」预留思考预算。
② 「许愿」不是省掉需求文档
掘金复刻者第一轮只说「做个赛车游戏，能开、有赛道、有计时、能切视角」——能玩，但外观与细节明显平庸； 第二轮让模型比对官方案例、补全提示词（夜雨都市风、Three.js 单文件、HUD、碰撞检测、冲线结算），完成度才接近预期。 省掉的是「怎么做」，不是「要什么」；描述越细，重抽越少，账单越低。
③ 跑分要打折看，别只听官方口径
11 项基准均为官方自测、自选框架、无第三方复核（Terminal-Bench 用 Claude Code、DeepSWE 用 mini-swe-v2）。 DeepSWE 77.0 确实高于 Opus 5 的 74.0，但 Terminal-Bench 42.3 / ProgramBench 29.1 / HLE 42.6 仍明显低于 51.8 / 37.0 / 56.3。「超越旗舰」是挑着项目说的。
◈
落回光谱：四个官方案例没有一个在右端
故宫、赛车、Godot 复刻、Valley of Ages 全都是可运行、可 diff、可重跑的工程， 没有一个是「生成模型抽卡出片」。这恰好反过来印证了 结论一： 官方拿来证明「许愿式编程」的样本，选的仍是第二次能不能做出来这一侧。 另一个值得记的细节：同一份 CSDN 实测里，V4-Pro 在写作评测题中编造了「120 个片段、通过率 81%、P95 210ms」等数字， 而 Flash 只描述方法、不编结果——输出更长、语气更自信，和「更可信」是两件事。

7.2为什么 .motion 值得单独讲

它是目前把「代码即视频」写成规范的最完整尝试。核心只有一句： 

window.renderFrame = (frame, inputs) => {
  // 用已校验的输入渲染「请求的整数帧」
  // 同一输入必须允许独立跳帧，不依赖前序帧
  // 随机性必须显式种子；时序不得依赖挂钟
};

这三条约束把「动画」从「播放一段过程」变成了「一个纯函数」。一旦是纯函数， 它就能被分布式渲染、能被逐帧对比、能被 Git 做视觉 diff、能被 AI 稳定修改。 这不是格式问题，是范式问题。

包结构（ZIP）
motion.json 身份与运行时 / params.schema.json 可替换内容 / asset-manifest.json 素材与许可 / guide.json 素材角色与时长策略 / SKILL.md 给 AI 的入口 / integrity.json 哈希清单
明确划出的三条红线
① 签名与哈希不等于授权；② 开放格式不等于开放许可；③ 选择运行时前不得执行未知代码——拒绝路径穿越、符号链接、无界解压。

冷静的判断：规范仍是候选版，稳定版 1.0 未冻结，官方也声明这是 MotionGit 的起源格式、 并非外部认证标准。所以现在的最佳姿态是「照着它的约束写自己的模板」， 而不是「押注它成为行业标准」。

11 / 反例与风险

六条能推翻「Vibe Anything 已成熟」的理由

这一节是给自己拆台。如果以下六条有一条击中你，前面的乐观都要打折。

一 · 成本会失控，而且不透明
有创作者为一个热带岛屿烧掉 1874 美元；一个 3D 房间用掉 40 小时、8000 万 token； 一座滚筒城市消耗 74M token；一条意大利沉浸式提示吃掉 41.9 万 token。 「一次成型」是叙事，「平均几次成型」才是预算。 单价、缓存与谷时怎么折算，见 08 Token 成本参考——那里也说明了为什么这些数字不能直接互相对账。
二 · 会趋同：AI design smell
测试者反复提到一种可辨认的「AI 设计味」——扁平化、同一套偏绿的配色，跨项目复现。 风格趋同是概率模型的必然产物，因为它在最大化「平均值的好看」。 要摆脱，必须给出强约束（设计规范、参考板、禁用清单），而不是形容词。
三 · 「许愿」不等于「交付」
Willison 的划界至今有效：不审代码叫 vibe coding，审了、测了、能解释，才叫软件开发。 商业交付里，第二条标准才是准入线。任何以「一句话生成」为卖点的流程， 都要在最后补一道验收：跑得起来、改得动、说得清。
四 · 标准还在早期，资产授权是暗礁
.motion 仍是候选版，稳定版未冻结；开放格式 ≠ 开放许可—— 模板开源不代表字体、配乐、素材可商用。签名与哈希只证明来源，不授予权利。
五 · 专业软件的「最后一公里」仍要人
Blender MCP 官方明言无沙箱护栏；Tripo/Meshy 出的网格常需人工修法线、UV、命名。 AI 把「从 0 到 0.8」变得极便宜，但 0.8 到 1 的那段仍然最贵。 报价时如果把这段算成零，必然亏。
六 · 声音的授权链比画面脏得多

三条可以直接开始的动作

01
先建「母版」，再谈产能

选一个你反复做的题材，把它做成一份可复用的母版：一个 3D 场景 / 一套 PPT 主题 / 一份 .motion 模板。母版的价值是让第二次的成本降到第一次的十分之一。

02
把「抽卡」改成「排练」

凡是需要精确构图/运动的需求，先花半小时做预演，再进生成。预演不消耗生成额度，是这套体系里唯一免费的确定性。

03
用「重跑一次」当验收标准

任何交付前，重跑一次、换个视角、交给别人操作。三件事任一失败，说明你交付的是奇观而不是产线。

04
先把音频接进时钟，再谈配乐

别把音乐当后期。开工前定一件事：节拍走帧友好 BPM（120/100/90），还是先把 onset 量化到帧网格。这一步决定后面所有剪辑点准不准。

05
先算一次「重抽成本」，再开工

用自己的历史均值填 retries，别用「一次成型」报价。同时把母版前缀、缓存命中和谷时批次定下来——这三件事对账单的影响，比换模型大得多。
